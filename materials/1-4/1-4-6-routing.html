ルーティングプロトコル

情報通信ネットワーク 第6回(#6 ルーティングプロトコル)のまとめです。ルータがパケットの行き先を決めるしくみ(経路制御表・Longest Match)と、経路を自動で作る RIP・OSPF、パケットの分割(MTU)を学びます。

穴埋め:
経路制御とはホップ経路制御表特別なエントリーLongest Match静的と動的AS・IGP/EGP2つのアルゴリズムRIP無限カウントOSPFエリアMTUと分割練習問題

1経路制御(ルーティング) とは

  • 目的のホスト まで パケット を届けるためのしくみ。
  • パケットの IP ヘッダには送信元・宛先 IP アドレスが書かれている。ネットワークが複雑につながっていても、目的のノードまでの経路(ルート)を決める。
  • 経路制御が正しく動くことで、地球上のすべてのノードへパケットを送り届けられる。

2ホップバイホップルーティング方式

  • 1 ホップごとに次のルートが決まり、最終目的地までパケットが転送される。各ルータは「全経路」ではなく「次にどこへ渡すか」だけを知っていればよい。
  • ホップ(hop):ネットワークの1区間(MAC アドレスを使ってフレームが配送される区間)。ルータを中継せずに届く隣のホストやルータの NIC までの区間。
  • リピータやスイッチはホップの終端にはならない(L1/L2 の機器なので)。
  • たとえ:新幹線を乗り継ぐ旅で、各駅の窓口で「次の乗り換え駅までの切符」だけを買っていく。切符(MAC アドレス)は区間ごとに変わるが、目的地(IP アドレス)は変わらない。

3経路制御表(ルーティングテーブル)

  • IP パケットを 次にどのルータへ転送 すればよいかを書いた表。ルータはこの表にしたがってパケットを中継(ルーティング)する。
  • 表の中身:宛先ネットワークアドレスと、次に配送すべき隣のルータの IP アドレス(ネクストホップ)。
  • IP アドレスの ネットワークアドレス部 を使ってルーティングする(ホスト1台ずつではなく、ネットワーク単位で表を持つ)。
  • 確認コマンド:netstat -rn(Windows・Mac/Linux)。宛先・転送先(ゲートウェイ)・送信 NIC が並ぶ。

4経路制御表の特別なエントリー

エントリー内容
デフォルトルート登録されているどのネットワークアドレスにも一致しないときに使う経路。「0.0.0.0/0」または「default」と書く。
ホストルート特定の1台のホスト(IP アドレス)への経路。「IP アドレス/32」と書く。
ループバックアドレス127.0.0.0/8 の範囲(主に 127.0.0.1)。自分のノード上で動くプログラム同士の通信に使う。仮想 NIC(lo0 など)に設定され、物理ネットワークには流れない。

5ルーティングの様子と Longest Match 規則

  • パケット送信時、IP ヘッダの宛先 IP アドレスで経路制御表を検索し、一致するネットワークアドレスを探す。
  • 一致するものが複数あるときは、ネットワークアドレスのビット長が最も長いものを優先する(Longest Match 規則)。より詳しい(狭い)経路ほど優先される。

9RIP(Routing Information Protocol)

  • 距離ベクトル型の IGP(主に RIP2 が使われる)。
  • ルータは周期的に(30 秒間隔で)自分の知っている経路制御情報をブロードキャストで送信する。6 回(180 秒)連続で情報が届かないと、そのルータとの接続が切れたと判断する。
  • メトリックの単位は「ホップ数」= 通過するルータの数。受信した経路情報を他へ転送するとき、メトリックを 1 加算 する。
  • 受信した経路情報を距離ベクトルデータベースに保存し、そこからメトリックが 最小 の経路を採用して経路制御表を作る。

RIP2 の主な改善点

  • ブロードキャストからマルチキャスト(224.0.0.9)へ変更 → 無関係なホストの負荷を減らす。
  • サブネットマスクの情報を伝えられる → 可変長サブネットのネットワークの経路制御ができる。
  • 明示的な認証機能 → パスワードが違う RIP パケットを無視し、経路情報の偽装や改ざんを防ぐ。

10無限カウント問題とループ対策

無限カウント問題:障害が起きたとき、古い経路情報がルータ間で循環し、メトリックが無限に増えていく現象。

  • 対策①:メトリックの上限を「16」と決める(16 に達した経路は 到達不能 とみなす)。
  • 対策②:ある NIC から受け取った経路情報は、同じ NIC へは送り返さない(スプリットホライズン:Split Horizon)。

ループの外で障害が起きると、正しい経路になるまで時間がかかる。そこで:

  • ポイズンリバース(Poison Reverse):障害を検出したら、メトリック 16(到達不能)の情報を通知する。
  • トリガードアップデート(Triggered Update):30 秒周期を待たずに、すぐに通知する。

11OSPF(Open Shortest Path First)

  • リンク状態型の IGP。トポロジーデータベースを全ルータで共有し、ダイクストラ法 を使ってコストの合計が最小となる最短経路を計算する。
  • RIP は簡易なネットワーク向け、OSPF は複雑なネットワーク向け。
  • 各リンクのコスト(回線の帯域 などに応じた重み)をメトリックとして使う。管理者が自由に設定できるので柔軟に運用できる。
    → RIP は通過するルータが少ない経路、OSPF はコストの合計が小さい(速い回線を通る)経路を選ぶ。

OSPF の動作概要

  • 10 秒に 1 回 HELLO パケットをマルチキャストして隣のルータを確認。4 回待っても返事がなければ切断と判断。
  • 接続状態が変わったら、リンク状態更新パケットを送信して他のルータに知らせる。NLSA(ネットワークにつながっているルータの情報)、RLSA(ルータにつながっているネットワークの情報)。
  • 受信後、リンク状態データベースを作り、ダイクストラ法でメトリックが最短の経路を求めて経路制御表を作る。

12階層化されたエリアに分割して管理

  • リンク状態型はネットワークが大きくなると、トポロジーデータベースが大きくなり計算が大変になる。
  • ネットワークの論理的な領域を意味する エリア の概念を導入し、ネットワークを複数のエリアに分割して階層的に管理する。
  • あるエリアをバックボーンエリア(エリア ID = 0)とし、他のエリアはバックボーンエリアにつなぐ。
  • エリア境界ルータは距離情報だけを伝える → 経路情報を減らし、計算の負荷を軽くする。
  • スタブエリア:エリアからの出口となるエリア境界ルータが 1 つしかないエリア。エリア外の経路情報は伝えなくてよく、エリア境界ルータがデフォルトゲートウェイになるように経路情報を流すだけでよい。

13IP パケットの分割処理と再構築処理

  • データリンクごとに最大転送単位 MTU(Maximum Transmission Unit)が異なる。例:Ethernet・Wi-Fi = 1500 オクテット(ジャンボフレーム対応なら 8000〜16000 オクテット)。
  • フラグメンテーション(分割処理):パケットが途中のデータリンクの MTU を超える場合、IP 層でパケットを細かく分けて送る。再構築は最終目的地のホストでのみ行う。
  • IP データグラム(ペイロード)部分だけを分割し(UDP の場合)、分割後のデータには IP ヘッダだけを付け、分割されていることを示すフラグをセットする → 断片の始まり・中間・終わりが分かる。
  • この分割はルータにとって大きな負荷。ルータはフィルタリングなど高度な処理もするので、できるだけ分割したくない。

経路 MTU 探索(PMTUD:Path MTU Discovery)

  1. 送信元ホストは IP ヘッダに分割禁止フラグ(DF)を設定して送信する。
  2. 途中のルータで MTU オーバーが起きたら、ルータはパケットを破棄し、「ICMP Destination Unreachable(Fragmentation Needed)」で 次のリンクの MTU を送信元へ通知する。
  3. 送信元ホストは通知された最小 MTU に合わせて、最初から分割して送る → 途中のルータで分割しなくて済み、ルータの処理負荷を減らせる。

答え答えと解説

答え:6

IP ペイロードは UDP ヘッダ込みで 8192 + 8 = 8200 オクテット。1 つのパケットに入るのは 1500 − 20 = 1480 オクテット。8200 ÷ 1480 = 5 余り 800 なので 5 + 1 = 6 個(1480 × 5 + 800)。
