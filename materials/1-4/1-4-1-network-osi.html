1スタンドアロンからネットワークへ

  • スタンドアロン:コンピュータ単体で利用。作業ごとに別々のコンピュータを使い分ける。
  • ネットワーク利用:コンピュータをネットワークで接続し、処理を サーバ に集約することで、ユーザのコンピュータから利用できる。

コンピュータ通信から情報通信環境へ

  • 初期:管理者が指定した 特定 のコンピュータ同士を接続(プライベートなネットワーク = LAN)。業務データのやりとりが中心。
  • インターネット:LAN 同士を接続したものが WAN、世界中の ISP(Internet Service Provider)を相互接続したものがインターネット。
  • さらに進化すると、空気や水のように意識されない存在に(Digital Inclusion)。

2コンピュータの利用形態の変遷

年代をタップすると説明が出ます。

バッチ処理

  • プログラムやデータをまとめて 一括 処理する方式。パンチカードや紙テープに記録して読み込ませる。
  • 当時のコンピュータは高価で巨大。ユーザは計算機センターまでカードを持って行き、オペレータに実行を依頼した。

TSS(Time Sharing System)

  • 1台の大型コンピュータ(ホスト、メインフレーム)に複数の 端末(キーボードとディスプレイを備えた入出力装置。パソコン とは違う)を接続。
  • ホストと端末を 通信回線 でスター型に接続し、複数のユーザが 同時 にホストを利用できる。
  • インタラクティブ(対話的)な操作が可能になり、使い勝手が格段に向上。

コンピュータ間通信 → コンピュータネットワーク

  • 1970年代に通信回線の利用制限が撤廃され、コンピュータ間を回線で接続できるように。複数のコンピュータで 分散処理 が可能に。
  • Ethernet の誕生(1973年、Xerox パロアルト研究所のロバート・メトカーフら)。1980年に DEC・Intel・Xerox(DIX)が Ethernet version 1 を発表。
  • TCP/IP の標準化(1982年)→ 異なるメーカーのコンピュータ同士で相互接続できるネットワークが登場。
  • 4.2BSD(UNIX 系OS)のリリース(1983年):TCP/IP を標準実装した世界初のOS。

インターネット

  • WWW(World Wide Web)の誕生:CERN のティム・バーナーズ=リーが発明(1989年)。1990年12月20日に世界初のWebページ公開。
  • NCSA Mosaic(1993年):テキストと画像を同じウィンドウに表示できた最初のブラウザ。
  • Windows 95(1995年):TCP/IP を搭載し、一般の企業や家庭にインターネットが普及し始める。

3プロトコルとパケット通信

プロトコル

  • コンピュータ同士が通信するための約束事。使用するプロトコルが同じなら、メーカーの異なる CPU や OS のコンピュータ間でも相互通信できることが保証される。
  • プロトコルが定める内容:データの フォーマット やサイズ、通信の 手順 など。

パケット通信

  • 大きなデータを小さく分割して送る方法(パケット = 小包)。
  • パケットは、送りたいデータと、制御情報を書いた ヘッダ からなる。
  • プロトコルは、ヘッダに書く情報と、その情報をどう処理するかを定義する。

4プロトコルの標準化と階層化

メーカーの異なるコンピュータ間でも自由に通信したい → 各社のプロトコルを共通化する = 標準化

OSITCP/IP
正式名などOpen Systems Interconnection(開放型システム間相互接続)インターネットの標準プロトコル
標準化した組織ISO(国際標準化機構)IETF(Internet Engineering Task Force)
現在OSI のプロトコルは普及していない大学や ICT 企業が中心に標準化。インターネットで使われている

プロトコルの 階層化

  • 通信に必要な機能を複数の階層に分割(ネットワークアーキテクチャ)。複雑なプロトコルを単純化できる。
  • 一部の層のプロトコルを変えるだけで機能を変えられる(柔軟性・拡張性が高い)。変更はその層の中で完結する(独立性・保守性が高い)。
  • インタフェース:上位層と下位層の間でサービスをやり取りするときの約束事。
  • プロトコル:通信相手と同じ階層でやり取りするときの約束事。

5OSI参照モデル

  • 通信に必要な機能を 7つの階層 で定義したもの。プロトコルを設計するときのガイドライン。
  • プロトコルについて議論するとき、このモデルの階層に基づいて「どの層の話か」を示すことが多い。
  • 送信側:上 位層から 下 位層へデータを渡す(ヘッダの 付加)
  • 受信側:下 位層から 上 位層へデータを渡す(ヘッダの 除去)
層名前役割
7アプリケーション層アプリの中の通信に関係する部分を定義(例:宛先 B さん・送信元 A さん・本文)
6プレゼンテーション層データの 表現 形式を定義(文字コード、画像・動画フォーマットなど)。コンピュータ固有の形式 ⇔ ネットワーク共通の形式に変換。符号に変換する = エンコード、元に戻す = デコード
5セッション層セッション(= 通信の開始から終了まで)の開始・終了・管理。コネクションをいくつ、どう張るかを判断する
4トランスポート層コネクションの確立・切断、確認応答や再送制御でデータ転送の 信頼性 を確保
3ネットワーク層送信ホストから受信ホストまでデータを配達。IPアドレス で宛先を識別し、中継器(ルータ)が転送先を決める
2データリンク層通信媒体で直接つながった機器同士でデータをやり取り。MACアドレス(物理アドレス)で機器を特定
1物理層ビット列 を 電圧 の高低や 光 の点滅に変換。ケーブル・コネクタの形状、周波数、変調方式などを定義
