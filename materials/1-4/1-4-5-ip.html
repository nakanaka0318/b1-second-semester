IP(Internet Protocol)と IP アドレス

情報通信ネットワーク 第5回(#5 IP)のまとめです。パケットを世界中の目的のコンピュータまで届ける IP と、その住所にあたる IP アドレス(ネットワーク部・ホスト部、サブネットマスク)を学びます。

1インターネット層と IP

  • TCP/IP のインターネット層は、OSI 参照モデルの ネットワーク層(L3) にあたる。この層の機能は OS に実装されている。
  • 上の層から受け取る単位はセグメント/データグラム、この層の単位は パケット、下の層(データリンク層)の単位はフレーム。
  • IP は TCP/IP の心臓部とも言えるインターネット層のプロトコル。IPv4 はインターネットの誕生から現在まで最も多く使われてきた IP(本科目はこちら)、IPv6 は IPv4 アドレスの枯渇問題から標準化された新しい IP。

用語の定義

用語意味
ホストIP アドレスが付けられた機器の総称。ただし経路制御(ルーティング)は行わない。
ルータIP アドレスが付けられ、ルーティングを行うネットワーク機器。異なるネットワークを接続する。ゲートウェイとも呼ぶことがある。
ノードホストとルータをあわせた機器の総称。

2インターネット層の役割

(1) パケットの構築と再構築

  • 上位層から受け取ったセグメント/データグラムを「パケット」と呼ぶ小さな単位に分割する(フラグメンテーション)。
  • 分割したデータにヘッダを付ける:宛先・送信元 IP アドレス、フラグメントオフセット(元データの中での位置)など。
  • 受信側は、下位層から受け取ったパケットをフラグメントオフセットの値に基づいて順序を整理し、すべてそろったら再構築(復元)する。

(2) 異なるネットワーク間でのデータのやり取り

  • IPアドレス による通信相手の特定:インターネット層におけるノードの識別子。TCP/IP で通信するすべてのノードは IP アドレスを設定しなければならない。データリンクの種類(有線・無線など)にかかわらず同じ形式。
  • 途中の中継器(ルータ)は、パケットに書かれた宛先アドレスを見て、どのネットワークに送るかを決めて転送する。
  • → ネットワークにつながっていれば、世界中のコンピュータにデータを届けることができる。

3ルータ/レイヤ3スイッチ

  • ネットワーク層でネットワークを接続する装置。複数の NIC を持ち、異なるネットワークに接続する。宛先 IP アドレスにしたがってパケットを中継する。
  • 異なるデータリンク同士でも相互接続できる。
    • ブロードバンドルータ:Ethernet(有線LAN)と IEEE802.11(無線LAN)
    • モバイルルータ:IEEE802.11(無線LAN)と 4G/5G(無線WAN)
  • (前回のブリッジ/レイヤ2スイッチは MAC アドレスで、ルータは IP アドレスで転送先を決める。)

5IP アドレス

  • 32ビット の正の整数値(IPv4 の場合)。232 = 4,294,967,296 = 約 43億 個の IP アドレスを定義できる。
  • 8 ビットずつの 4 組に分けて、2進数を10進数で書き、ピリオドでつなぐ(ドット付き10進記法)。各組は 0〜255 の値。

IP アドレスは NIC ごと

  • IP アドレスはノードごとではなく、NIC ごとに割り当てる。
    • ルータは 2 つ以上の NIC を持ち、それぞれに IP アドレスを設定する。
    • ホストも複数の NIC を持つことがある(有線LAN、無線LAN、4G/5G)。1つの NIC に複数の IP アドレスを付けることもできる。
  • TCP/IP ネットワーク上で重複した IP アドレスは設定 できない(ユニークでなければならない)。どのノードにルーティングすればよいか一意に決まらなくなるため。

6IP アドレスの構成

ネットワークアドレス部(ネットワーク部)ホストアドレス部(ホスト部)
ネットワークを識別する値。IP アドレスの前半。データリンクのセグメントごとに重複しない値を割り当てる。同じセグメントにつながるノードの NIC には同じ値を設定する。 ノードを識別する値。IP アドレスの後半。同じセグメント内で重複しない値を割り当てる(他のセグメントのノードと同じ値でもかまわない)。

住所にたとえると、ネットワーク部が「町名」、ホスト部が「番地」。同じ町の中では番地が重ならなければよく、別の町なら同じ番地があってもよい。

7アドレスクラス(クラスフルアドレッシング)

インターネット普及初期の区別のしかた。クラス A〜D の 4 つが定義され(未使用のクラス E もある)、クラスごとにネットワーク部の長さが固定されている。先頭のビットでクラスが決まる。

クラス先頭ビット範囲ネットワーク部1ネットワークのアドレス数
A00.0.0.0〜127.255.255.2558 ビット224−2 = 16,777,214
B10128.0.0.0〜191.255.255.25516 ビット216−2 = 65,534
C110192.0.0.0〜223.255.255.25524 ビット28−2 = 254
D1110224.0.0.0〜239.255.255.255マルチキャスト通信に利用(ネットワーク部・ホスト部の概念なし)

「−2」は、ホスト部が全部 0(ネットワークアドレス)と全部 1(ブロードキャストアドレス)の 2 つがノードに使えないから。

9クラスフルの無駄と IPv4 アドレスの枯渇

  • クラス A は1つのネットワークに約1600万台、B は 65,534 台、C は 254 台つなげる。家庭はクラス C で十分だが、オフィスでは足りないので A・B を取得 → 実際につなぐ台数は限られるので、使われない IP アドレスが大量に発生。
試すアドレス使用率
  • インターネットの発展で通信機器が爆発的に増え、IP アドレスを管理して各地域・各国の ISP へ配る組織の在庫がなくなった(2011年)。IPv4 アドレスの総数は約43億個で、2007年の世界人口(約67.5億人)より少ない。
  • IP アドレスが使えない = インターネットに接続できない
  • 対策:① IP アドレスの効率的な利用(サブネット) ② プライベート IP アドレスと NAT の利用 ③ IPv6 への移行

10対策① サブネットとサブネットマスク

  • ネットワークを複数の サブネット に分割する → サブネット単位で使える IP アドレスの数を少なくできる。
    例:クラス B(172.16.0.0)を4つに分割 → 216−2 = 65,534 個 が 1サブネットあたり 214−2 = 16,382 個に。
  • サブネットマスク を導入し、ネットワーク部の長さを 自由 に設定できるように拡張した(クラスレスアドレッシング)。
    • サブネットマスクは IP アドレスと同じ書き方(例 255.255.255.0)。
    • ビットが連続して 1 になっている範囲がネットワーク部。
    • IP アドレスとサブネットマスクの論理積(AND)を計算すると、ネットワークアドレスが求まる。

算出例(スライド p.19〜20)

IP アドレス 172.20.100.52、サブネットマスク 255.255.255.192(クラス B に 10 ビットのサブネットマスクを追加した場合)

IP アドレス 10101100.00010100.01100100.00110100 172.20.100.52 サブネットマスク 11111111.11111111.11111111.11000000 255.255.255.192 └──── ネットワーク部 26bit ────┘└ホスト部 6bit AND の結果 10101100.00010100.01100100.00000000 172.20.100.0 ← ネットワークアドレス

ブロードキャストアドレスはホスト部のビットをすべて 1 にする。第4オクテットで考えると、11111111 − 11000000 = 00111111、10進数で 255 − 192 = 63。ネットワークアドレスの第4オクテット 0 に足して ∴ ブロードキャストアドレス = 172.20.100.63。

このネットワークに設定できる IP アドレスは 172.20.100.1〜172.20.100.62(62 個)= 26−2。使えるアドレス数が少なくなる = 未使用の IP アドレスを少なくできる。

11演習(スライド p.23)

ホストがある LAN に接続すると、IP アドレス 192.168.100.150、サブネットマスク 255.255.255.128 が設定された。この LAN のネットワークアドレスとブロードキャストアドレスを答えよ。また、この LAN に接続できる通信機器は最大何台か。

ヒント1まずどこを見る?

255 のオクテットはそのまま残るので、第4オクテット(150 と 128)だけ 2 進数にすれば十分です。

ヒント22進数にすると

150 = 10010110
128 = 10000000

マスクの 1 は先頭 1 ビットだけ → ネットワーク部は 24+1 = 25 ビット、ホスト部は 7 ビット。

答え答えと解説

ネットワークアドレス 192.168.100.128 / ブロードキャストアドレス 192.168.100.255 / 最大 126 台

AND:10010110 AND 10000000 = 10000000 = 128 → ネットワークアドレスは 192.168.100.128。

ホスト部 7 ビットをすべて 1 に:10000000 + 01111111 = 11111111 = 255(255 − 128 = 127 を 128 に足す)→ 192.168.100.255。

台数:27 − 2 = 128 − 2 = 126(ネットワークアドレスとブロードキャストアドレスは使えない)。範囲は 192.168.100.129〜192.168.100.254。

上の「IP アドレス計算機」の「演習(p.23)」ボタンでも確かめられます。

12コマンドで自分の IP 設定を確認する

  • Windows:ipconfig /all。「物理アドレス」= MAC アドレス、「IPv4 アドレス」、「サブネット マスク」を見る。
  • Mac/Linux:ifconfig(Linux では ip addr も)。ether = MAC アドレス、inet = IPv4 アドレス、netmask = サブネットマスク。lo0 はループバックインタフェース(第6回で解説)。
en0: flags=8863<UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500 ether 38:f9:d3:0d:6e:39 inet 192.168.1.19 netmask 0xffffff00 broadcast 192.168.1.255

ifconfig の netmask は 16 進数で表示される。0xffffff00 = ff.ff.ff.00 = 255.255.255.0(/24)。だから broadcast は 192.168.1.255 になっている。

13対策② プライベート IP アドレス

  • インターネットに接続しない、独立した LAN の内部だけで使える IP アドレス。次の範囲が決められている。
クラス範囲
A10.0.0.0〜10.255.255.255(10.0.0.0/8)
B172.16.0.0〜172.31.255.255(172.16.0.0/12)
C192.168.0.0〜192.168.255.255(192.168.0.0/16)
  • 上の範囲以外の IP アドレスをグローバル IP アドレス(インターネットに接続できる IP アドレス)として再定義した。
  • プライベートネットワークをインターネットにつなぐ場合は、NAT でプライベート IP アドレスをグローバル IP アドレスに変換する必要がある(第10回で解説)。
  • 各組織の中で同じプライベートアドレスを使い回せるので、グローバルアドレスを節約できる。

上の IP アドレス計算機の「種類」欄で、入力したアドレスがプライベートかどうかも確かめられます。

14対策③ IPv6 への移行

  • IP アドレスの空間そのものを広げる新しい IP。IPv6 アドレスは IPv4 アドレスの 4 倍の長さ(128 bit)。
  • アドレス数は 2128 ≒ 3.4×1038 ≒ 340澗(かん)個(IPv4 の 296 倍)。天文学的な数。
  • 16 ビットごとに 4 桁の 16 進数(小文字)で書き、コロンで区切る(コロン区切り16進表記)。詳しくは 3 年後期「情報通信システム」で。
