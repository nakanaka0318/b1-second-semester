1TCP/IP 登場の背景

回線交換 方式

  • 電話(1876年、グラハム・ベル):1本の回線を 2者 の通話が 占有(通話中は他の人は使えない)。
  • テレックス網を使った通信(1950年代):初期のコンピュータネットワーク。
  • 課題:交換機間の回線数より通信したいコンピュータが多いと通信できない/次の転送がいつ始まり終わるか予想できない/交換機が止まると通信できない。

軍事研究と 分散 型ネットワーク

1960年代、アメリカ国防総省(DoD)が中心となって研究。ネットワークの一部が攻撃で壊れても、迂回経路でデータが届き通信が止まらないネットワークが望まれた。

パケット交換 方式

  • 1965年、イギリス NPL のドナルド・ワッツ・デイヴィスが提唱。
  • 1本の回線を 共有 することにより、多対多 の通信を実現。ページ上部のシミュレーションで違いを確かめましょう。

2TCP/IP の標準化と RFC

OSI(ISO)は1990年代に標準化されたがほとんど普及しなかった(実際に動くプロトコルを早く実装できず、技術革新に対応する仕組みもなかった)。TCP/IP の標準化の特徴は次の2つ。

  1. オープン:IETF で議論。議論のメーリングリストには誰でも参加できる。
  2. 実際に使える技術:実装しながら仕様を決め、複数の実装を持ち寄って相互接続実験をくり返す。

RFC(Request For Comments)

  • IETF で標準化されたプロトコルに関するドキュメント。インターネットで無料公開。
  • 作成された順に通し番号が付く。例:IP = RFC791、TCP = RFC793。

「TCP/IP」という言葉の意味

TCP と IP だけでなく、IP で通信するときに必要な多くのプロトコル群の総称(インターネットプロトコルスイート)。

分類例
アプリケーションプロトコルHTTP, SMTP, FTP, TELNET, SNMP
トランスポートプロトコルTCP, UDP
インターネットプロトコルIP, ICMP, ARP
経路制御プロトコルRIP, OSPF, BGP

インターネットの構造

  • ISP が家庭や企業に接続サービスを提供。各地の LAN は ISP の NOC(Network Operation Center)に接続。
  • 一次 ISP 同士は IX(Internet Exchange)で相互接続し、世界の Tier1 ISP がつながることで各国のインターネットがつながる。
  • Tier1:インターネット全体の経路に到達できる大手/Tier2:Tier1 に接続し地域内に強い/Tier3:エンドユーザに接続を提供。

3TCP/IP の階層モデル

OSI 参照モデルが 7 階層であるのに対し、TCP/IP 階層モデルは 4 階層(物理層を分けると5階層)。

各層の役割

  • ハードウェア(L1):Ethernet、電話回線、無線LAN など。TCP/IP では内容を定義していない。
  • ネットワークインタフェース層(L2):NIC を動かすデバイスドライバ。NIC には MACアドレス が設定されている(世界で唯一、製造時に設定され変わらない)。
  • インターネット層(L3):IP を使い、IP アドレスに基づいてパケットを転送。宛先は途中の機器ではなく終端のホスト。届かなくても再送しない(信頼性の ない プロトコル → ベストエフォート)。
    • 補助:ICMP(異常を送信元に通知)、ARP(IPアドレスから MACアドレスを取得)
    • 経路制御:RIP、OSPF/セキュリティ:IPsec
  • トランスポート層(L4):ポート番号 でアプリケーションを識別。
    • TCP:コネクション型。再送制御・順序制御で到達性を保証。ウィンドウ制御・輻輳制御で効率よく。
    • UDP:コネクションレス型。信頼性の仕組みはないが制御パケットが少ない。動画や音声などリアルタイム性が必要な通信、ブロードキャストやマルチキャスト をする場合に利用。
  • アプリケーション層(L5〜L7):多くは クライアント/サーバ モデル。サーバはあらかじめ 起動 して要求を待ち、クライアントは 任意 のタイミングで要求する。例:Web は HTTP で通信し、HTML でデータを表現(HTML はプレゼンテーション層に相当)。

5アドレス

  • アドレス:通信の送信元と宛先を特定する 識別子。1つのアドレスで1台のホストを特定する(唯一性)。
  • 同じアドレスのホストがあると 正しく通信できない → 必ず重複しないように設定する。
層アドレス例
アプリケーション層ホスト名/ドメイン名/FQDN/メールアドレス/ユーザ名www / meijo-u.ac.jp / www.meijo-u.ac.jp
トランスポート層ポート番号TCP 443 / UDP 53
インターネット層IPv4 / IPv6 アドレス192.0.2.1 / 2001:db8::1

6パケットの構造

各階層で、送るデータ(PDU)に ヘッダ を付ける。下位層から見れば、上位層から受け取ったものはすべて1つのデータ。

アプリケーション層データメッセージ
トランスポート層TCPデータセグメント
インターネット層IPTCPデータパケット
ネットワークIF層EthernetIPTCPデータFCSフレーム
  • ヘッダには少なくとも宛先アドレス、送信元アドレス、上位層のプロトコルが入る → 受信側はどのプロトコルにデータを渡せばよいか判断できる。
  • FCS(Frame Check Sequence):ハードウェアで計算してフレームの末尾に付ける。ノイズなどでフレームに 誤り が生じたことを 検出 するためのデータ。

OSI は実際に動くプロトコルを早期に実装できず、急速な技術革新に合わせてプロトコルを改良する仕組みもなかった。一方 TCP/IP は、IETF で誰でも参加できるオープンな議論で標準化され、仕様を決める段階から実装して相互接続実験をくり返すことで、実用性の高いプロトコルになったため普及した。
